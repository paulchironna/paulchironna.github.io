4-20mA Automated Tank Fill Build

PLC controlled pump system with 4-20mA level input, automatic fill control, fault monitoring and interlocking, and MODBUS RTU HMI status display

This project builds on my basic PLC motor control project, expanding from discrete logic to analog process control. I integrated an analog input card, which gave me experience setting up 4-20mA field wiring and scaling inputs inside the software. I also incorporated an HMI that pulled data from the PLC's registers over MODBUS RTU to display fault messages and statuses using AdvancedHMI software.

My goal was to make the project as scalable as possible. I used hardware capable of accepting 120 or 240V input power, and created subroutines within the program to accommodate additional I/O. I also added extra relays for physical status indicator availability and extra registers for supervisory or PID control inputs for future versions.

System Overview: Wiring

I created a simplified schematic to plan power distribution, control wiring, and fault signals. Incoming 120 or 240V power feeds the contactor, power monitor, and 24V power supply. I used an HOA switch for operator control, with signal wiring sent to the PLC and HMI for status display. The E-Stop and overload NC contacts are wired in series with the contactor coil, as well as an auxiliary relay the PLC energizes to break the coil circuit on a detected fault. Faults latch until reset by cycling the HOA switch.

Critical safety functions are handled exclusively in hardware. The E-Stop and overload contacts are de-energize-to-trip and are in series with the coil independently of the PLC, so an open circuit will always stop the motor. The auxiliary relay covers process and diagnostic faults like loop failure or feedback loss, which aren't safety critical in this application. It sits in the same series string as the safety contacts, so a diagnostic fault interrupts the coil in hand mode as well as auto. Fault handling and fail-safes are always process dependent, and I scoped my layers of protection accordingly. One revision I would make is adding feedback to the auxiliary relay so that it will alarm if it fails to energize or break the circuit in a fault state.

Ladder Logic

The program was the most challenging part of this project for me. Rung order and the use of subroutines became critical rather than just helpful. I have no subroutine or direct monitoring for hand mode outside of the contact for the indicator. This was to allow the motor to be run in case of a program loss or error. The auto subroutine could have just lived on the main page, but I wanted to set it up so that I could easily add more instruments down the road as the build gets more complex. The biggest challenge in the programming, however, came with fault handling and communication with the HMI software.

Setting up the MODBUS RTU settings so that baud rate, parity, stop bit, etc. matched was straight forward and it took some research to match up the addressing formats between programs. Once I had these communication sorted, I developed my fault logic for my eight distinct faults: CH1 Short Circuit, CH1 Open Circuit, Thermal Overload Tripped, E-Stop Pressed, Contactor Failure, HOA Switch Malfunction, IO Module Failure, and IO Module Missing 24V. Not shown is my input scaling, which simply just set 4-20mA to a 0-100% scale. 4mA being 0% allows me to detect an open circuit reliably if the reading is ever lower than 0. I added timers and deadbands where needed for hysteresis and if all conditions for a given fault were met, an assigned bit would be turned on. The status of these bits were packed into a register which was copied and sent to the HMI each scan.
